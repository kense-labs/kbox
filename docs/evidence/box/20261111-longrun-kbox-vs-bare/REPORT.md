# kbox vs 裸跑：10 个长程任务性能损耗对比

- 生成时间：2026-11-11T12:19:38Z（UTC）
- 后端：`kbox run -i --rm`（MicroVM + OCI 镜像） vs `node apps/cli/lib/bin.js --profile acp`（宿主直跑）
- 模型：deepseek-flash / reasoning low；10 个任务 × 3 个依赖回合 × 2 端 = 20 次独立运行
- 校验：两端全部通过宿主 oracle 的字节级比对 = 10/10 对；bare PASS 10，kbox PASS 10；输出字节一致 10/10 对；重试 0 次

## 净结论

1. **表面速度差不是 kbox 的功劳**。含启动的总墙钟 kbox 快 17.246 s（约 34%），但其中 16.578 s 来自裸跑本地构建特有的 ~18–21 s agent bootstrap（与密钥无关，复现多次）。扣除启动后配对 Δ 中位仅 -0.487 s（约 -1.6%），落在 DeepSeek API 抖动区间内，**长任务稳态耗时无显著差异**。
2. **MicroVM 没让算力变慢**。3 条命令在后端内的实测执行时长之和 Δ 中位 -0.07 s；纯宿主参考计算均值 5.39 s/任务。CPU burn、gzip、矩阵乘、哈希链、文件扇出在 guest 内与宿主内基本等价；`session/new` RTT 中位 bare 158.5 ms vs kbox 87.0 ms，kbox 的 ACP 通道反而更快。
3. **kbox 的真实代价是资源，不是墙钟**。每任务宿主侧多耗 3.52 CPU-秒（约 +50%）、峰值常驻内存多 544.75 MB（约 3.1×）。这是 VM shim 的固定 footprint，与任务类型几乎无关（10 个任务的 Δ 都在 2.9–4.4 CPU-秒、470–555 MB）。
4. **一次性成本要单列**。全新 `K_HOME` 首次组装 ext4 rootfs 本轮实测 72.833 s（此前独立测得 76 s）；缓存命中后每个新 VM 到 initialize 约 4.178 s。镜像 177.7 MB，每个隔离 K_HOME 的稀疏 ext4 实际占用约 780 MB。

## 全量指标

- **任务总墙钟（含启动）**：bare 中位 50.984 s，kbox 中位 33.716 s，配对 Δ 中位 -17.246 s（范围 -18.861 ~ -12.67 s）。
- **任务总墙钟（扣除 agent 启动）**：bare 中位 30.104 s，kbox 中位 29.575 s，配对 Δ 中位 -0.487 s（范围 -2.475 ~ 3.169 s）。
- **进程/VM 启动到 initialize**：bare 中位 20.867 s，kbox 中位 4.178 s，配对 Δ 中位 -16.578 s（范围 -17.922 ~ -15.604 s）。
- **3 个回合的 ACP prompt 耗时之和**：bare 中位 29.755 s，kbox 中位 28.877 s，配对 Δ 中位 -0.794 s（范围 -2.787 ~ 2.731 s）。
- **3 条命令在后端内的实测执行时长之和**：bare 中位 5.514 s，kbox 中位 5.417 s，配对 Δ 中位 -0.07 s（范围 -0.488 ~ -0.02 s）。
- **3 个回合首包延迟之和**：bare 中位 15799.4 ms，kbox 中位 14907.45 ms，配对 Δ 中位 -754.2 ms（范围 -3923.4 ~ 2841.2 ms）。
- **宿主侧后端进程树 CPU 时间**：bare 中位 7.027 s，kbox 中位 10.569 s，配对 Δ 中位 3.52 s（范围 2.872 ~ 4.412 s）。
- **宿主侧后端进程树峰值常驻内存**：bare 中位 254.05 MB，kbox 中位 799.65 MB，配对 Δ 中位 544.75 MB（范围 469.6 ~ 555.1 MB）。

## 一次性成本（不计入每任务稳态）

- `bare` 全新 HOME 冷启动到 initialize：**18.893 s**（initialize RTT 18876.2 ms）
- `kbox` 全新 HOME 冷启动到 initialize：**72.833 s**（initialize RTT 72819.7 ms）
- kbox 首次为新的 `K_HOME` 组装 guest-native ext4 rootfs 本轮实测 72.833 s（此前独立测得 76 s，release 二进制），两者一致；每个隔离 K_HOME 的稀疏 ext4 实际占用约 780 MB，镜像存储 177.7 MB。缓存命中后不再重复。
- 裸跑没有 VM/rootfs 一次性成本，但本地构建的 agent bootstrap 每次进程启动都要付一次固定 ~18–21 s。

## 口径与边界

- **公平性**：10 个任务的 prompt 文本、seed 字节和 `node -e` 命令两端完全相同；宿主独立执行同一命令生成参考输出并做字节级比对；A/B 顺序逐任务交替。
- **长程定义**：每个任务是一个 ACP 会话内的 3 段依赖管线（生成 → 变换 → 在途等待并证明整链），含确定性 CPU burn、I/O 扇出/目录树、压缩、矩阵、哈希链与 1.2–2.1 s 的在途等待。
- **隔离基础设施差异**：刻意让模型只执行给定命令并回一个词，把 LLM 决策方差压到最低，剩下的差异才反映承载层；prompt 回合耗时仍由 DeepSeek API 主导，不应解读为 kbox 开销。
- **CPU/RSS 采样**：macOS libproc `proc_pid_rusage`，CPU 时间按 mach timebase 换算；kbox 统计所有 kbox/krun 宿主进程（含 VM shim），bare 统计 node 进程树。短生命周期子进程在 0.2 s 采样间隔下可能少计，因此 CPU 秒数应视为下界。
- **混杂因素**：两端是同一 dsh 0.2.2-rc.1 的不同构建（宿主本地 vs OCI 镜像），且 Node 22.22.2 vs 24.22.2；本地构建的 initialize 存在与密钥无关的固定 ~18.5 s bootstrap。因此「含启动」的总墙钟差异主要来自 agent 构建，而非 kbox；判断 kbox 自身开销应以「扣除启动」「命令内时长」「CPU/内存」为准。
- **统计**：每任务 1 次配对，无重复置信区间；API 抖动范围内的小幅正负差异不构成显著结论。
