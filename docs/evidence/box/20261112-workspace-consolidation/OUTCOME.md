# Single-workspace consolidation and root lint inheritance

Date: 2026-11-12. Host: macOS/arm64. Toolchain: repository `rust-toolchain.toml`
channel 1.97.1. Result: PASS for the compile, lint, unit-test and layout-check
scopes below. No native runtime claim is made for Windows or Linux.

## Problem

`crates/oci-runtime` declared its own `[workspace]` with 8 members while the
root workspace also listed 7 of the same paths (18 members total). The same
packages therefore belonged to two workspaces, each with its own
`[workspace.dependencies]`, `[workspace.lints]`, `Cargo.lock` and toolchain
(root 1.97.1 vs nested 1.98.1). This violates `AGENTS.md` ("Do not create
another Cargo workspace or root lockfile") and Microsoft
`M-CRATES-FLAT-FOLDER`. Two stale files were also unreferenced leftovers:
`crates/box/Cargo.toml.box-workspace` and `crates/box/rust-toolchain` (content
`stable`, which would override the pinned toolchain for cargo commands run
under `crates/box/`).

`kbox` had no `.github/workflows`, and only 8 of 19 members had
`[lints] workspace = true`, so the root `[workspace.lints]` was nearly inert.

A dependency audit showed all 20 keys of the nested `[workspace.dependencies]`
already existed at the root, and none of the 8 crates inherited
`[workspace.package]` values (each writes version/edition explicitly). The
functional difference was the `derive` feature on `zeroize`.

## Changes

### Layout

- Removed `crates/oci-runtime/Cargo.toml` (the nested `[workspace]`,
  `[workspace.package]`, `[workspace.dependencies]`, `[workspace.lints]` and a
  duplicate `oci-spec` patch already present at the root),
  `crates/oci-runtime/Cargo.lock` and `crates/oci-runtime/rust-toolchain.toml`.
- Removed `crates/box/Cargo.toml.box-workspace` and `crates/box/rust-toolchain`.
  The former was an unreferenced, stale manifest (version 3.2.7, edition 2021,
  tonic 0.11, axum 0.6). Its only non-obsolete content was a comment about a
  patched `h2` that relaxes HTTP/2 `:authority` validation for UDS gRPC
  clients (hyperium/h2#487, grpc/grpc#38142). That patch is NOT enabled in the
  root manifest, and the vendored `crates/box/third_party/h2` tree is
  untouched. The rationale is recorded here so it is not lost with the file.
- `Cargo.toml`: added `crates/oci-runtime/crates/containerd-shim` to `members`
  (now 19) and gave the root `zeroize` dependency the `derive` feature the
  nested workspace supplied.
- `Cargo.lock` was regenerated by cargo (989 added / 72 removed lines). Every
  changed `version =` line is an addition: no existing dependency was upgraded
  or downgraded. The growth comes from `containerd-shim`'s
  `[target.'cfg(unix)'.dependencies]` (`containerd-shim 0.11`,
  `containerd-shim-protos 0.11`, ttrpc, zbus, ...). The crate is not in
  `default-members`, so ordinary builds are unaffected.

### Lints

- Merged the nested workspace's 4 deny rules into the root `[workspace.lints]`
  (`unsafe_op_in_unsafe_fn`, `dbg_macro`, `todo`, `unimplemented`) so the 8 OCI
  crates keep their previous red line after the nested workspace is gone.
- Added `[lints] workspace = true` to 9 previously uninheriting members.
  17 of 19 members now inherit the root lints.
- Two documented local exceptions remain: `crates/box/shim` (49 pre-existing
  FFI calls inside `unsafe fn` would be E0133 under the deny; this crate never
  had the deny) and `crates/box/third_party/mkext4` (keeps its stricter
  `unsafe_code = "forbid"`). Neither is a relaxation of an existing red line.
- `crates/runtime/src/driver.rs`: the `NoSnapshotDriver` test mock used
  `unimplemented!("... is not under test")` 6 times. Changed to `panic!("...")`
  with a comment: these are contract-violation guards, not unfinished work,
  and `clippy::unimplemented` is denied workspace-wide.

### Guardrails

- `scripts/check-workspace-layout.py`: pure-stdlib, read-only check for one
  workspace declaration, one first-party `Cargo.lock`, one toolchain file,
  member existence, and lint inheritance with the two named exceptions.
- `.github/workflows/verify.yml`: layout contract; Linux `cargo check` and
  `cargo clippy` with `K_DEPS_STUB=1` and `protobuf-compiler`; and a Windows
  cross check of `kbox-shim` so the `#![cfg(target_os = "windows")]` named-pipe
  module keeps compile coverage.
- `AGENTS.md`: both contracts recorded next to the existing rules.

## Retained failures and detours

- `kbox-cri` needs `protoc` for prost-build; it is not installed on this host.
  This is pre-existing and unrelated to the layout change. Verification used
  `--exclude kbox-cri`, and the new CI installs `protobuf-compiler`.
- The first consolidated run with `--locked` correctly refused to update
  `Cargo.lock` (new member + new feature). An `--offline` retry failed because
  `containerd-shim 0.11` was not cached; allowing the normal crates.io fetch
  completed resolution.
- Enabling `[lints] workspace = true` on all 19 members initially produced 51
  errors (49 E0133 + 2 aggregate), all in `kbox-shim`: `kbox/context.rs` 25,
  `vm_launch.rs` 22, `main.rs` 2. The shim keeps its previous local state
  instead of being mechanically rewritten; this is a separate code change.
- The first full clippy pass after lint inheritance found 6
  `clippy::unimplemented` errors in `crates/runtime/src/driver.rs`; fixed as
  described above, then 0 errors.
- `cargo fmt --all -- --check` is intentionally not a gate: the repository has
  historical rustfmt differences. `git diff --check` and touched-file checks
  were used instead.
- `K_DEPS_STUB=1` was used for every check. Without it `klibksys` build.rs
  attempts a source build of libkrun and panics on the macOS deployment-target
  query during cross compilation.
- When cargo output is piped, `set -o pipefail` is required; otherwise a failed
  cargo run appears as exit code 0 from `tail`.

## Explicitly not claimed

- **No physical crate move.** `crates/oci-runtime/crates/*` and `crates/box/*`
  paths are unchanged, so directory references (including historical
  `docs/evidence` records) stay valid. One 2026-11-05 evidence line records
  `cargo check --manifest-path crates/oci-runtime/Cargo.toml --workspace`; that
  specific command no longer reproduces because the nested manifest was
  removed. The historical evidence was deliberately not edited, per
  `AGENTS.md`. The flat-folder shape of `M-CRATES-FLAT-FOLDER` is therefore NOT
  fully achieved; only the dual-workspace defect is removed. A physical
  flattening is a separate, larger change that was explicitly not selected.
- No Windows or Linux native runtime test was run. Cross-compilation proves
  compilation only (`AGENTS.md`).
- The new CI workflow was not executed remotely; its steps mirror the commands
  verified locally.
- `kbox-shim`'s 49 unsafe-fn calls were not fixed, and the inherited deny was
  not lowered. Both facts are recorded, not hidden.
- The KCL dual source (`path = "../kcl"` here vs `git rev` in krun), the
  hand-synced cross-repo wire schema strings and krun's host-ARCH guest
  architecture assumption are out of scope and unchanged.
- krun's own in-progress, uncommitted directory refactor was left untouched;
  only its `cargo check --locked --all-targets` was re-verified (rc=0).
- No commit, push, or rewrite of historical evidence was performed.
