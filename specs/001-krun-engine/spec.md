# KRun 本地引擎入口与流式执行扩展

创建：2026-11-10。状态：已规划，待实现；未创建特性分支。负责路径：`crates/box/{core,runtime,cli}`，必要时复用／扩展 `crates/runtime` 的操作回执接线。

总计划由独立 KRun 仓库维护：[实施计划](../../../krun/docs/implementation-plan.md)。本 epic 只覆盖版本化引擎入口和流能力，不实现完整 MateHarness、能力装配或推理循环。

## 用户场景

### US1：独立 CLI 可靠控制执行环境（P1）

外部 KRun 不链接本机 kbox 源码，使用稳定身份提交、查询和停止操作；CLI 被杀不导致重复执行或假报停止。

独立测试：同一实例并发提交、响应丢失后按原 request ID 重试，以及引擎重启后的真实执行观测。

1. 相同请求重试，返回原操作或真实待确认状态，不创建第二个执行环境。
2. 较新的停止意图先到，旧启动请求迟到，后者被拒绝且不能留下活动资源。
3. 不支持的版本、能力或原生平台，在执行副作用前明确拒绝。

### US2：标准输入输出完整用于 ACP（P1）

已准备好的执行代次通过无 PTY 通道运行进程；原生 stderr、退出码与 stdin EOF 可分别观察，输入不因重试而重复执行。

独立测试：真实客体进程在半关闭 stdin 后继续输出，使用慢消费者和大于 unary 输出上限的数据，再验证唯一退出结果和清理。

1. stdin 关闭只结束输入方向；读取剩余输出和退出事件，不立即丢弃尾部。
2. 第二个连接不能抢占同一 Harness 进程。
3. 完整断线后流不可恢复，不重放输入；进程树与本代次临时资源由引擎清理。

## 要求

- FR-001：公开版本与能力发现、操作提交／查询、执行观测、停止、日志、独立流式进程能力，使用类型化输入和稳定错误。
- FR-002：复用 ExecutionManager 和 ManagedRuntimeClient，不建立第二份 VM／进程生命周期记录，不接管其他调用方资源。
- FR-003：请求绑定 caller、engine ID、instance ID、request ID、intent revision、计划摘要和精确 generation；generation 由引擎分配。
- FR-004：已接收请求持久化后才返回接收回执。崩溃后按原身份对账，不能把传输超时当作执行失败后重建。
- FR-005：在真实资源副作用处拒绝旧意图和旧 generation，包括迟到创建；只在网关检查不满足要求。
- FR-006：控制帧和数据队列有上界，支持背压与 stdin 半关闭。首版流不可恢复，不承诺断线后的输入重放。
- FR-007：流能力独立于 Runtime unary Exec；不改变其 wire schema、结果大小与重试语义。ACP 扩展在字节流中完整保留。
- FR-008：凭据在单独控制路径绑定，不进入 argv、持久回执或 ACP 前导流；必要能力缺失明确拒绝。

## 所有权与边界

KRun 保存用户意图、待派发请求和最后观测；引擎保存已接收 revision 及现有 Runtime 回执的引用。ManagedRuntimeClient 负责操作回执，ExecutionManager 负责实际资源，流会话只拥有连接映射。

v1 为同一用户的本地 IPC。先验收 macOS/arm64 与 Linux/aarch64 客体；未原生测试的平台不新增支持声明。未知状态保留清理责任，不能报告资源已经退出。

恶意／故障用例包括：伪造资源 ID、相同请求 ID 不同正文、过大／截断帧、无权限本地连接、双连接抢占、旧 revision 晚到、进程退出与断线竞态、引擎重启、尾部输出与日志混流。

## 成功标准

- SC-001：US1／US2 的 hermetic 故障测试通过，无重复进程和相互矛盾的终态。
- SC-002：原生客体流测试证明半关闭、大输出、背压、子进程清理和 generation 校验；取消及恢复不依据 mock 声称支持。
- SC-003：独立客户端通过版本发现和控制／数据通道完成测试，不依赖 `../kbox` 源码、不解析人类输出。
- SC-004：记录实际命令、计数、平台、制品和清理观测；现有 Runtime unary 与 pool 测试不被弱化。

本文件是规划，不是接受验收的证据；完整三 Harness 与五类能力验收属于后续里程碑。

## 只读诊断扩展（2026-11-11）

`engine-diagnostics.v1` 增加 `diagnose` 查询，沿用现有私有 IPC 和同用户鉴权。
返回引擎身份、版本、平台和现有宿主虚拟化探测结果。探测在 blocking worker
执行，不申请 VM、不提交意图、不对账或清理其他执行。失败返回明确的不可用状态，
不转发包含宿主数据的任意错误正文。它不证明客体依赖、镜像内容、模型认证或任务可用。
旧客户端继续使用 discovery；新客户端在扩展未公开时不得猜测支持。
验收覆盖协议拒绝、无资源副作用、真实 macOS 查询和旧 OCI 路径兼容；其他宿主不据此声明支持。
